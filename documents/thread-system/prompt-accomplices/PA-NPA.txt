WHAT THIS THREAD IS
-----------------------------------------------------------------

The Needpedia phone app. Its job is to make a person's phone buzz
when something happens on needpedia.org that they asked to hear
about.

Tony's aim for himself: a button in the app that only a top-level
admin (master_admin) sees, leading to a page listing everything he
is set to be alerted about, with a switch per item for off / alert /
alert plus more.

Tony's phone is a Cricket Outlast, an ordinary Android phone. He has
given up on his PinePhone Pro.

-----------------------------------------------------------------
WHERE EVERYTHING RUNS
-----------------------------------------------------------------

The app itself runs on the phone. There is no server for the app.
Changing it means putting a new version on the phone.

needpedia.org runs on Amazon's servers (AWS). The alert-sending code
lives there. Murtaza reviews and deploys anything that goes onto
needpedia.org. Tony pays him.

Google's free notification service carries an alert from that server
to the phone. It is always running on an Android phone and wakes the
app, so the app does not need to be open. The project on Google's
side is named update-needpedia, project number 550163998966. Whose
Google account owns that project is UNCONFIRMED.

Vercel hosts Tony's separate public inbox page project. It is not
part of the phone app.

CONFIRMED BY READING THE CODE, 26 SEPTEMBER 2026
-----------------------------------------------------------------

Five small code files. Newest change 23 October 2024.

Branches main, master and fixes/fcm-notification all point at the
same last change. There is no extra notification work in the third
branch. Nothing by Mubasher exists anywhere in the project.

The published app signs phones up with the PRACTICE copy of the site
(staging.needpedia.org), for both login and phone registration. An
app built from this code would never get alerts from the live site.

After login the app shows the Needpedia name, the tagline, one
YouTube video, and a menu whose only item is Logout. It does not
check what kind of account you have.

BUG: if an alert arrives while the app is open on screen, nothing
appears. The code for that case sits in its own file and is never
switched on.

BUG: if an alert arrives while the app is closed, the code tries to
open the browser immediately instead of waiting for a tap.

BUG: logging out does not unregister the phone, so it keeps
receiving that account's alerts.

Needpedia sends phone alerts for three things, not two: a new
private message, an edit to a tracked post, and the once-a-day
summary. Each depends on that account's notification setting being
instant or daily.

Every alert is only a count, for example "You have 1 notifications
about posts". No post name and no link. Alerts about specific things
need new sending code on the site whichever direction the app goes.

A master_admin rank is a plain yes/no switch on the account record,
and nothing in the code strips it out of what login sends back. So
the app is very likely already told, and simply never looks.
