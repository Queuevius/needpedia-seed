WHAT THIS THREAD IS (28 Sep 2026)
John's self-hosted test-site package, and the improvements worth making
to it. It turns one Linux machine into a small test server running
several independent copies of Needpedia at once. Each copy has its own
web address, its own database and its own cache. A copy sleeps when
nobody is using it and wakes itself when somebody visits.

Why it exists: volunteers need a place to show work in progress to
Tony. GitHub Codespaces (GitHub's in-browser computer) was tried and
rejected: a Codespace stops after 30 minutes of no use and its shared
address dies with it, which is unworkable across an 8-hour time
difference.


WHERE IT IS (28 Sep 2026)
Delivered by John on 26 September 2026 as his milestone 6, in the m6/
folder of his branch:
https://github.com/eberechi10/Needpedia/tree/milestone6-testsite
Tony's instructions: m6/README-TONY.md in that folder.

Three parts: a front door that reads the web address and sends the
visitor to the right copy (Traefik); a doorman that starts and stops
sleeping copies (Sablier, free and open source); and the Needpedia
copies themselves. Also included: a per-copy setup file, a starter
script, and a script that loads sample content.

Status: not yet tested by Tony.


DECISIONS (Tony, 27-28 September 2026)
- Standalone. Volunteers show their work here. After Tony approves it,
  they submit the code on GitHub for the lead developer's review. The
  lead developer does not need to approve this package itself.
- Nothing goes to the lead developer until the automatic part is built
  and tested: a volunteer pushes work, and a copy appears at its own
  address on its own, with nobody typing anything. Tony wants John to
  build that part too.
- Thread name TS. Its public posts use the name TS.


KNOWN ROUGH EDGES (Tony asked John to fix these, 27 Sep 2026)
- The example settings file hard-codes one local port, so a second copy
  collides on it.
- If the site starts before its database is ready, the database setup
  is skipped. The instructions give a manual restart as the workaround
  rather than a fix.
- The commit with John's Debian fix also re-indents a lot of Dockerfile
  lines that did not need touching. Tony asked John to strip that out.


WHAT IT CAN'T DO YET (the list Tony brought, 28 Sep 2026)
- A copy per branch, appearing on its own when someone pushes work.
- Encrypted connections (https). Right now people would type passwords
  in the clear. This must be fixed before it faces the open internet.
- Sending email. Password resets and confirmations go nowhere.
- Any access control. Anyone with the address can walk in.
- Extras wanted later: the world map, a cheap AI with a spending limit,
  video.
- Cleaning up. Old copies pile up and eat disk until someone removes
  them.
- A plain limit on how many copies can run at once. Each copy is a
  full site plus its own database.


OPEN DESIGN QUESTION: WHICH MACHINE (Tony's call, not decided)
The existing server was at 77% of a 15 gigabyte disk running production
and staging, so this probably needs its own machine. Three ways:
- A second small AWS machine alongside the existing one. Same account,
  same bill, kept apart from the live site.
- Tony's own hardware. No monthly cost, but it runs on his electricity
  and internet, and it is down when his power is.
- Squeezed onto the existing server. Cheapest, and the worst idea: a
  runaway test copy could take the live site down with it.


IDEAS TO WEIGH (not decided, 28 Sep 2026)
- An AI reviewer for submitted code changes: CodeRabbit, free for
  public projects. It reads each submitted change and posts comments on
  it on GitHub. It would give the lead developer changes that have
  already had one read, and give volunteers feedback before Tony looks.
  Switching it on for the main project is Tony's and the lead
  developer's decision. Tony also mentioned a feature showing which
  changes depend on which; that could not be confirmed as CodeRabbit's
  and may belong to a different tool.
- Name ideas for it, or for a home-made version: Hopper, Porch,
  Checkpoint, Second Look, Waystation, Bridge. (Not "Doorman": that is
  already the nickname for the part that wakes and sleeps copies.)

DECIDED BY TONY, 30 SEPTEMBER 2026
- WHICH MACHINE: Tony's own desktop for now, because it is fast and
  cheap. A move to a server comes later.
- A SPARE COPY ALWAYS WAITING: when copies are made automatically, one
  copy is already set up, awake and ready. When a volunteer takes it, it
  becomes theirs, and the system sets up a new spare for the next
  person. Tony wants the spare fully awake (instant to use) if the
  machine can afford the memory.
