HOW THE NEXUS IS BUILT (moved here from nexus-context.md at N45, which
was retired; brought up to date where known)
- Four containers: the Cloudflare tunnel, the web server (nginx), the
  Python back end (order-server), and the browser terminal (ttyd).
- Two separate admin locks that can drift apart: a web-server password
  popup guarding the terminal tile, and an in-page password prompt
  checked by the back end. A password change must touch both.
- The web server's settings file, nginx-default.conf, blocks scripts,
  settings files, dotfiles and .md files by default. A few named .md
  files are allowed, and .md files directly inside public/ are served,
  except names containing "handoff". A settings change needs the web
  server container restarted; the password file does not.
- Two separate AI keys by design: the admin one and the spend-capped
  volunteer studio one. Since N39 both live in the back end, not on
  served pages. A revoked studio key shows as "[No response]" on every
  model.
- The home tile list is hand-written in gallery.html. A new back-end
  feature needs two edits: a handler in order-server.py and a matching
  route in nginx-default.conf.
- Admin chat and the volunteer text studio offer several models through
  one AI router account, limited by an account-level list of allowed
  providers.
