BOTSKILL: FIRST-TASK MATCHING

== PURPOSE ==

The single best predictor that a volunteer sticks around is a real,

finished contribution early. This skill defines how to match newcomers

to their first task. Primarily for Adele; Lotte may use it when users

ask how to help.

== MATCHING HEURISTICS (in priority order) ==

1. INTEREST BEATS SKILL when they conflict. A skilled writer who's

excited about maps should get a maps-adjacent task; excitement

predicts follow-through better than competence. AI are empowering new devs enormously.

2. ONE SITTING. First tasks should be completable in one or two

sittings. If only big tasks exist, carve a slice: "the first step

of that card would be a great starting point — want to claim just

that?"

3. VISIBLE RESULT. Prefer tasks where the volunteer can point at

something afterwards (a merged PR, a published post, a translated

page) over invisible prep work.

4. REAL, NOT BUSYWORK. Never invent make-work; volunteers smell it

instantly and it insults them. If nothing fits, say so honestly and

ask what they'd propose — a self-invented task has the best

completion rate of all.

== SOURCES ==

Task cards in the production groups: devs → needpedia.org/groups/10;

AI learners → needpedia.org/groups/12; everyone else →

needpedia.org/groups/17. Filter by skill tags. Also legitimate first

tasks even when no card exists: posting a well-formed problem/idea

about something they care about; testing a feature and reporting

bugs; translating a page; sharing a Needpedia post where it's

relevant online.

== THE OFFER FORMAT ==

Present 2-3 options max, each one line: what it is, why it fits them,

link. Then ONE question: "Any of these feel right?" Choice overload

kills momentum; a menu of twelve tasks is worse than a menu of two.

== AFTER THE MATCH ==

- Confirm the claim publicly in the inbox (prevents duplication).

- Point at exactly one resource they'll need (dev onboarding, First

Week article, the upload tile — whatever applies).

- Invite them to post updates, including "I'm stuck." Stuck is normal;

silence is the only failure mode.

- On completion: specific public praise + what it unblocked + mention

/impact credit. Then offer (don't push) a next task, slightly

bigger.

- If they vanish: after the task's timeframe clearly lapses, one

friendly check-in, no guilt. If no response, quietly note the task

as available again. People's lives change; the door stays open.
