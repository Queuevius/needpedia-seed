Build a Chrome extension (Manifest V3) in the current directory. Purpose: passively capture claude.ai conversations and POST them to a self-hosted server. Five files, all in this directory:

1. manifest.json — Manifest V3. name "Nexus Capture". content_scripts matching only https://claude.ai/* (content.js). background service_worker: background.js. options_page: options.html. permissions: storage. host_permissions: https://claude.ai/* and https://nexus.needpedia.org/*.

2. content.js — Runs on claude.ai pages only. At the very top of the file, define named constants for the DOM selectors used to find: the conversation container, individual message elements, a way to tell user messages from assistant messages, and the message text content. Comment above these constants: "If captures stop arriving, claude.ai's page layout likely changed — check these selectors first." Logic: use a MutationObserver on the page body. Whenever mutations occur, restart a 4-second idle timer. When the timer fires (page has been quiet 4 seconds), extract: the conversation ID from the URL (the segment after /chat/), a title (page title or first user message truncated), and an ordered array of {role, content} for every visible message. For file uploads, represent them in the content as the literal string "[file uploaded: NAME]" using the filename shown in the UI. Compute a simple fingerprint (e.g. message count + hash of last message content) and skip sending if unchanged since last send for this conversation ID. Send the extracted data to background.js via chrome.runtime.sendMessage with type "CAPTURE".

3. background.js — Listens for "CAPTURE" messages from content.js. Reads the capture token from chrome.storage.local (key "captureToken"). If no token is stored, do nothing (no error, no notification — silent no-op). If a token exists, POST to https://nexus.needpedia.org/capture with header X-Capture-Token set to the stored token, JSON body {claude_id, title, messages}. No retry logic needed — next mutation cycle will naturally resend if it fails.

4. options.html — Minimal settings page. One labeled text input for the capture token, one always-visible "Save" button (not hover-triggered). Show a brief "Saved" confirmation message after saving. Plain, readable styling, no framework needed.

5. options.js — On Save click, write the token to chrome.storage.local under key "captureToken". On page load, if a token is already stored, pre-fill the input (but you may mask/truncate it in display) so Tony can tell it's already set.

Important constraints: no build step, no bundler, no external dependencies — plain JS/HTML only, since this loads via chrome://extensions "Load unpacked". Keep each file readable with comments, since a non-developer may open them later. Do not hardcode any token value anywhere in the code.
